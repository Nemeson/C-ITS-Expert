# C-ITS Expert 1.5.0

Embedded MCP milestone plus a full code-review hardening pass. Full details: `CHANGELOG.md`.

## Highlights
- **MCP capability profiles** (`device`, `host`, `ci`) and an **edge zipapp** (`cits-edge`) with zero
  third-party dependencies: reproducible build, SHA-256 checksum, hardened systemd unit.
- **IEEE 1609.2 / ETSI TS 103 097 envelopes are now read.** Signed messages expose their BTP port (R01)
  and are decoded (R06). Signatures are **not** verified; encrypted messages stay opaque.
- **Bounded by design:** request size, file size (`CITS_MCP_MAX_FILE_BYTES`), packet count
  (`CITS_MCP_MAX_PACKETS`), output size (`CITS_MCP_MAX_OUTPUT_BYTES`).
- **Geometry fix:** MAPEM `node-XY` offsets are 1 cm with X = East / Y = North. Earlier versions
  exported lanes 10x too long and mirrored.

## Upgrade notes (behaviour changes)
| Area | Before | Now |
| :--- | :--- | :--- |
| `CITS_MCP_ROOTS` | applied to `device` only; `;` separator | applies to **all** profiles; platform separator (`os.pathsep`); `/` refused |
| Oversized tool output | returned as is if not truncatable | `{"error": "output too large", ...}` |
| Tool hidden by profile | still callable via `tools/call` | `-32601` |
| Unexpected tool error | exception text returned | `Internal error: <Type>` |
| Lane without type (GeoJSON/KML) | `ingress` + stopline marker | `unknown`, no marker |
| Node without lat/lon | placed at 0,0 | dropped |
| GLOSA `YELLOW` | treated like red | always "prepare to stop" |
| `xml_content` / `lisa_xml` (MCP) | non-`<` strings opened as files | text only |

## Known limitations
- No signature/certificate verification for secured frames (planned for 1.6.0).
- The 1609.2 reader was validated against vectors built from the specification, not a real secured
  field capture; please verify with one.
- BTP ports 2010, 2013, 2019 still to be checked against ETSI TS 103 248.
